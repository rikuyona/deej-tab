# ハードウェアとファームウェア

## 部品

| 部品 | 型番 | 数 |
|---|---|---|
| マイコン | Arduino Nano 互換（CH340C・USB Type-C） | 1 |
| スライダー | Bourns PTL60-15R0-103B2（60mm・10kΩ B カーブ・赤 LED 付き） | 5 |
| 回転ボリューム | SH16K4B103L20KCCI（16mm 型・10kΩ B カーブ・6mm ローレット軸 18 山） | 1 |
| ノブ | 3D プリント、または ABS-28 | 1 |
| LED 用抵抗 | 330Ω（180Ω〜1kΩ） | 5 |

- ボリュームはすべて B カーブ（直線）なので、値は位置に比例します（中央 ≒ 512）
- LED の抵抗：赤 LED は順方向電圧 1.8V・データシートの条件 20mA。5V で 20mA 以下にするには 160Ω 以上。330Ω で約 10mA

### PTL60 の端子

データシートの穴の図は上から見た図で、「3 は 1 と同じ線上、B は E と同じ線上」です。4 本の列を手前にして上から見ると、摺動子（2）が左端です（実物で確認済み）。

## 配線

| 部品 | 端子 | つなぐ先 |
|---|---|---|
| スライダー 1〜5 | 1 | GND |
| | 3 | 5V |
| | 2（摺動子） | A0〜A4 |
| | B（LED＋） | 抵抗 → D3 / D5 / D6 / D9 / D10 |
| | E（LED−） | GND |
| | L | つながない（ダミー端子） |
| 回転ボリューム | 両端 | 5V / GND |
| | 中央 | A5 |

- D0 / D1 は USB シリアルに使うので空けておきます
- LED のピンは PWM が使えるものから選んでいます

### Nano の端子の並び（USB 側 → 反対側）

| 側 | 並び |
|---|---|
| D 側（ケースの右端側） | D12 D11 **D10 D9** D8 D7 **D6 D5** D4 **D3** D2 **GND** RST RX0 TX1 |
| A 側（スライダー 4 側） | D13 3V3 REF **A0〜A5** A6 A7 **5V** RST GND VIN |

- A 側は A0〜A4 の線をスライダーへまっすぐ出せます
- GND は D 側の 4 本目（端から約 11.7mm）を使います。A 側の GND は押さえ（[case.md](case.md)）の縁から約 1.1mm しかありません
- 押さえがかぶさるのは 1 本目（TX1・VIN）と ICSP（2×3）だけで、どれも使いません

## ファームウェア（`firmware/deej-6ch-led`）

公式 deej の `deej-5-sliders-vanilla` を元にした 6 チャンネル版です。値の送り方は公式と同じなので、公式 deej からも使えます。

### 値の読み取り

- 1 回読み捨ててから 8 回平均します（`OVERSAMPLE`）。ピンを切り替えた直後は前のピンの電圧が残るためです
- 3 未満の変化は前の値のままにします（`HOLD`。0 と 1023 は必ず出す）。これで触っていない時の揺れが ±6 から 0 になりました
- 約 10ms ごとに `v0|v1|v2|v3|v4|v5`（生の値 0〜1023）を送ります。端の位置の補正はアプリ側で行います（deej 互換のため）

### PC とのやりとり

Nano → PC：

| 行 | 意味 |
|---|---|
| `512\|0\|1023\|…` | スライダーの値（6 本） |
| `@ID\|deej-6ch-led\|1.3\|1E5F90CC` | ファームウェアの名前・版・コントローラーの ID。起動時と `@I` を受けた時に送る。公式 deej は `@` の行を読み飛ばす |

PC → Nano：

| 行 | 意味 |
|---|---|
| `@L\|g\|m0\|…\|m4` | LED の状態。`N` 普通・`O` 消灯・`D` 暗く（割り当て先が動いていない）・`B` 明滅（100% 超え）・`P` 点滅（ピックアップ待ち）。`g=1` は一時停止中 |
| `@V\|l0\|…\|l4` | LED を音に合わせる時の音の大きさ（-48dB〜0dB を 0〜255、15 回/秒） |
| `@P\|DIM=20\|…` | LED の光り方の数値（1 行 60 文字まで）。変わった時と 5 秒ごと |
| `@C\|番号\|下端\|上端` | スライダーの端の位置。変わった時と 5 秒ごと |
| `@B` | 起動アニメを再生する |
| `@I` | ID を聞く |

- 3 秒何も来なければ、PC なしの光り方に戻ります
- 形が違う行・範囲外の値は捨てます（範囲外の数値は範囲に収める）

### LED

PC なしの光り方（PC からの指示がない時）：

- 普段は暗めに点灯し、操作したスライダーだけ明るくして戻す
- 0 まで下げたら消灯
- しばらく操作がないと減光（`SLEEP_MS`）
- 起動時に光が流れる

光り方は普段・起動・操作した時の 3 つを選べ、数値は `paramTable` の変数です（名前と範囲は `leds.PARAM_LIMITS` と同じ。テスト `test_firmware_matches` で確かめる）。計算はアプリの `leds.led_brightness()` と同じにしてあり、設定画面のプレビューと仮スライダーはこれを使います。

- 波紋（操作した LED から端まで広がる）は、割り当て先が動いていない（`D`）LED にも出します。`D` の LED を操作した時は `INACTIVE_TOUCH` から広げます（真ん中より隣が明るくならないように）
- 明るくする時は速く、暗くする時はゆっくり変えます。点滅・一時停止の明滅はそのまま出します

### EEPROM

| 番地 | 中身 |
|---|---|
| 0〜 | LED の光り方の数値（`paramTable` の順） |
| 200〜 | スライダーの端の位置（6 本分） |
| 240〜 | コントローラーの ID（目印＋32 ビット） |

- 受け取ってから 2 秒後に保存します（`EEPROM.put` なので同じ値なら書かない）。PC から外しても同じ光り方になります
- **数値を足す時は `paramTable` の最後に足します**（順番で保存しているため）

### コントローラーの ID

CH340 は USB のシリアル番号を持たないので、別の USB の口に差すと COM 番号が変わります。チップには書き込めないので、ファームウェアに ID を持たせました。

- 初めて起動した時に、アナログ入力の揺れと `micros()` から 32 ビットの ID を作って EEPROM に保存します（書き込み直しても消えない）
- アプリ側の探し方は [app.md](app.md#コントローラーをつなぐ)
