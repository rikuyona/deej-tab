# 基板版（`pcb/`）

スライダー 5 本とノブを 1 枚の基板に載せ、Nano とはケーブル 3 本でつなぐ版です。配線を楽にするのが目的で、Nano・USB-C の位置・ファームウェア・アプリ・ピンの割り当ては配線版と同じです。作り方・部品・ケーブル・組み立て・注文は [pcb/README.md](../../pcb/README.md) にあります。ここには、決めたことと理由をまとめます。

状態：設計済み・**未検証**（基板を発注・組み立てて確かめていない）。データとガーバーは先に公開しています（Releases の `pcb-v0.1.0`。プレリリース）。実物で確かめて直したら版を上げ、プレリリースを外します。

## 決めたこと

### Nano は載せず、ケーブルでつなぐ

「天板を閉じると基板の裏のソケットが Nano に刺さる」案は、基板の裏と Nano の上面のすき間が 5.4〜6.7mm しかなく、低いソケットとピンの切りそろえが要るのでやめました。Nano 側は 13 本ハンダ付けし、基板側は挿すだけにします。

### ケーブルは JST ZH の 3 本（電源 3 ピン・LED 6 ピン・信号 6 ピン）

秋月のコネクター付コード（ZH 相当、片側ハンダメッキ）をそのまま使えるからです。

- 秋月で ZH 相当のコードは 6P(H) 105719・6P 112604・3P 黒白赤 118272 だけ（同じ名前のコードでも、2P(A)・2P(E)・3P 黒橙白は PH、2P(B) は EH、7P と 6P 黄緑茶白黒赤は SH）。基板側の ZH 横向きは 2〜6 ピン（S?B-ZR-3.4）
- 分け方は「電源・信号・LED」。信号は Nano の A 側（A0〜A5 が連続）、LED は D 側の並びと同じ順
- JL（LED）と JA（信号）は Nano のすぐ左に縦に並べ、口を Nano へ向けます。端子の並びが Nano の端子と同じ前後の順なので、コードはまっすぐ右へ出て隣の Nano に付きます。JP（電源）はボリュームの近くで口は手前
- 1 番の向き：データシートの No.1（口から見て左、基板が下）を裏に付けた向きに直すと、「口が手前なら上から見て右端」「口が右なら奥の端」。コードの色と番号の対応は、Nano に付ける前にテスターで確かめます
- 経緯：PH 13 ピン（秋月に無い）→ XH 7＋6 → 秋月の ZH コード。配置も、口を奥向き（コードが奥の壁に当たる）→ 手前向き → 窮屈なので右へ広げる → Nano の横に縦に並べる今の形

### ノブは基板用のボリューム JH16K6B103L20KC-H13

秋月 117390。今の SH16K4 と同じ Supertech 16K シリーズの基板用（10kΩ B）です。

- **軸は基板と直角（上向き）**。端子は本体の前寄りから下へ出て、軸と平行に後ろへ伸び（取付面の 3.4〜13.4 後ろ、軸の中心から 13）、軸と直角な基板に刺さります。正面図で端子が端面（小さな四角）として描かれているのが決め手（最初は軸が基板と平行の横向きと読み違えていた）
- 本体は取付面から 9.3 とスライダー（7.0）より深いので、今と同じくナットでパネルに留め、基板の左奥を本体の形（円 R9＋端子の付け根の四角）に切り欠いて通します。端子の途中（幅約 2.9・厚さ約 0.4 の板）を基板の長穴（3.3×0.9、`POT_SLOT`）でハンダ付けします
- パネルの穴・回り止め・印刷のノブ・目盛り（300°）は配線版と同じものが使えます
- ほかの候補：秋月の 114937（基板用薄型）は軸のないダイヤル。Alps RK09L（縦）は取付面から基板まで 10mm・M9・D カット軸で合わない

### 部品はすべてスルーホール

JLCPCB には基板だけを頼み、部品は手でハンダ付けします（最初は 0805 の面実装を JLCPCB で実装する案だった）。

- 基板の表はスライダー本体と天板（すき間 0.5）でふさがるので、部品の本体は裏、ハンダは表にし、表に出る足とハンダの所は天板の裏を 3mm 彫って逃がします（足のまわり 1.5 の四角。`outline.json` の `reliefs`）
- 抵抗（1/4W・足の間隔 10.16・寝かせる）はスライダーの右のすき間（X＋7.5）。スライダー 5 だけ右に余地がないので左
- 摺動子の 0.1µF（秋月 104065）は同じすき間、ノブの 0.1µF は JA の右奥、5V の 10µF（秋月 100464、足の間隔 5mm）は JP の奥
- 裏の部品と底ケースの床のすき間は、いちばん狭い所で約 2mm

### LED の抵抗は 150Ω

LED をなるべく明るくするためです。5V − ピンの降下 約 0.4 − 1.8V ＝ 2.8V ÷ 150Ω ≈ 19mA（配線版の 330Ω の約 2.2 倍）。120Ω（約 23mA）・100Ω（約 28mA）は LED のデータシートの条件 20mA を超えるので、150Ω を下限にしました。5 個で約 95mA。

## 基板の作り方（`make_pcb.py`）

KiCad 10 の Python（pcbnew）で動かし、部品の配置・配線・ベタ・DRC・ガーバー・部品の一覧まで一度に作ります。

- 2 層 1.6mm。外形は L 字（X 13〜113・V 13.5〜90.5 ＋ 左奥 X 13〜78・V 90.5〜113.5）で、100×100 に収まります。Nano の真上は切り欠き
- 座標はケースと同じ X と、基板の上を測った V（パネルの傾き 3.3° の分だけ Y より長い。スライダーの中心 Y＝51 で V＝Y）
- **配線は自動（Freerouting 2.4.1）**：スクリプトは部品の配置と信号の割り当てだけを決め、Specctra DSN に書き出して Freerouting（`-mp 200`）で配線し、SES を読み込みます。手配線では 5V の線と帯の線の並びが交差して組めなかったためです
  - GND は DSN の網から消して自動配線させず、表裏のベタでつなぎます（表裏をつなぐビアは自分で置く）
  - 線の幅は全部 0.3（5V も。流れるのは 0.1A 程度）
  - 結果：DRC エラー 0・未接続 0、別に書いた回路との突き合わせで違い 0、銅の形を重ねた独自チェックでひとつながり・ショート 0
- KiCad に ZH 横向き（スルーホール）の部品形状が無いので、スクリプトで作ります（`zh_footprint`。1.5mm ピッチ、ピン Φ0.5、パッドは KiCad の ZH 上向きと同じ 1.03×1.73・穴 0.73）
- スルーホール部品の原点は 1 番の足なので、足 2 本の真ん中に動かして置きます（そのまま置くと半分ずれてスライダーと重なった）
- スライダーの端子の向き：4 本の列を手前にして上から見て左から 2・1・L・E（`MIRROR = False`、実物で確認済み）

### 落とし穴

- Freerouting 2.4.1 は Java 25 以上が要ります（Java 21 では `UnsupportedClassVersionError`）。winget の Temurin（MSI）は管理者の許可待ちで止まったので、zip 版の JRE 25 を `%LOCALAPPDATA%\deej-tab\tools` に展開して使います（`make_pcb.py` が探す）
- 外形に円弧の切り欠きを入れると、作ったばかりの基板のまま `ZONE_FILLER` で塗ると塗りが空になります。保存して読み込み直してから塗ります
- ZONE の `GetLayerName` は表裏とも `F.Cu` を返しますが、ファイルには正しい層が入ります（表示だけ）
- 裏のベタは斜めの線でいくつかに分かれますが、表のベタとビアでつながっているので問題ありません

## ケース（`case.py --pcb`）

`case/out/pcb/` に出します。引数なしは配線版で、出力は前とバイト単位で同じです（split の演算の順番を変えると三角形の分け方が変わるので、配線版は元の式のまま）。

- 天板の厚さ 8.5（パネル 2＋本体 7−すき間 0.5。本体 7.0±0.5 の短い個体でも基板を押さない）。スライダーの爪は無く、**M2×4 皿ネジ 10 本**で留めます。スナップと四隅の柱は自動で合います
- 基板の外形・コネクター・部品の位置は `pcb/outline.json`（`make_pcb.py` が書く）から読みます
- 干渉チェックに基板・JH16K6・裏の部品とケーブルの出口・表に出る足・裏に出る端子とハンダ（2.4）を入れています。スライダー 4 の端子のハンダと Nano のすき間は 2.5mm
